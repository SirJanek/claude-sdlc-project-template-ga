# Toast

## 1. Purpose

Confirms a successful save without interrupting.

## 2. When to use

"Availability saved", "Profile saved".

## 3. When not to use

==Errors, never== (stage 0 decision) — use Alert or Error state next to the cause; anything needing action.

## 4. Anatomy

Box `--popover`, `--border-strong`, no shadow, text. Bottom right, `role="status"` (polite).

## 5. Variants

One. Built on Radix Toast; sonner not added (not in the plan).

<Canvas of={Stories.Visible} />

## 6. States

Appears, auto-hides after 4 s, pauses on hover/focus, F8 focuses the region.

## 7. Behaviour and accessibility

Keyboard and screen reader behaviour from Radix / native HTML; focus 2 px `--ring`, offset 2 px; targets ≥ 24 px, controls 40 px. Portals take the theme from `<html>`.

## 8. Content

English UI, sentence case, concrete DevMentor data (dates, zł, names). Actions name the verb.

## 9. Responsive behaviour

Full width up to its max width; no horizontal scroll at 320 px.

## 10. API

`ToastProvider duration`, `useSavedToast()` → `showSaved(text)`.

## 11. Code

```tsx
const showSaved = useSavedToast(); showSaved("Availability saved");
```

## 12. Do and don't

| Do | Don't |
|---|---|
| Use tokens only, no shadow (R01.1). | Hardcoded colours, `dark:` classes, entrance animations. |
