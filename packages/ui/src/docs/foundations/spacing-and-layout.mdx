# Spacing and layout

One scale (4, 8, 12, 16, 24, 32, 48, 64 px) used only through **relation tokens**: a component says
"between items in a group", never "8 px". Two densities exist on purpose (K1): lists are as tight as a
GitHub pull-request list (R01.1); the text session has more air between messages (R02.2).

Tailwind utilities: `gap-inline`, `space-y-stack`, `p-panel`, `py-section`, `px-list-row-x`, `py-list-row-y`,
`gap-thread-gap`. Any numeric spacing class (`p-5`, `mt-7`) or arbitrary value (`p-[13px]`) is a lint error.

## Layout

Content is a single column, left-aligned, with a maximum width of `--layout-max` (64 rem, the app's current
`max-w-5xl`). Check every screen at the three widths below; at 320 px nothing scrolls horizontally.

## Rules

| Rule | Source |
|---|---|
| Spacing comes from relation tokens; a number in a class is a lint error. | K1, prompt rule 3 |
| Lists are rows separated by `--border` lines, never cards in a grid. | R01.1, A03 |
| Flat navigation: Sessions, Profile, Payouts for mentors; mentees see only their sessions. No sidebar with sections. | R02.6 |
| Session layout: question and context beside the thread from 1024 px up, stacked below that. | R02.3 |
| Content is left-aligned; centring is for dialogs only. | A01 ("everything centred") |
| 320, 768 and 1440 px are checked for every screen; horizontal scroll at 320 px is a defect (the current admin header fails this). | audit 2026-10-19 |
