# Colour

Colour in DevMentor does two jobs and nothing else: it marks **the one primary action on a screen** and it
**names a state**. Everything else is a warm neutral. Source: referencje R01.3, R01.4, K2; tokens in
`packages/ui/src/styles/tokens.css` (approved `lekcja-06/tokeny.md`).

Three layers. Components use only the **semantic** layer below. The raw palette (`--dm-*`) exists only
inside the tokens file; a palette name in a component is a lint error (`pnpm lint:tokens`).

`--border` sits at about 1.3 : 1 and is allowed only as decoration (dividers, card outlines). Any element whose
only boundary is a border (outline button, text field) uses `--border-strong`.

## Rules

| Rule | Source |
|---|---|
| Colour is never the only carrier of meaning: a status badge always has a text label, a required field has text, an error has a message. | R01.3, WCAG 1.4.1 |
| One `--primary` surface per screen. A second call to action is an outline button or a link. | R01.5 |
| No gradients in backgrounds, text or buttons. No translucent or blurred panels. | A01 |
| State colours (`--status-*`) appear only on badges and inline notices, never on buttons. Buttons that destroy use `--destructive`. | R01.3 |
| Raw palette tokens (`--dm-*`), hex, `rgb()`, `oklch()` and Tailwind palette classes (`bg-indigo-600`, `text-white`) do not appear in components. | prompt rule 3 |
