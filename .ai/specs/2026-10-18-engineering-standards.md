# Spec: Adopt the engineering standards (migration steps 1–3)

**Intent:** [intent.md](../../docs/sdlc/intent.md) › Constraints (AI-native SDLC process) — enabling work
**Standard:** [.ai/docs/engineering-standards.md](../docs/engineering-standards.md)
**Status:** accepted · requested by Jan on 2026-10-18 (scope "steps 1–3 + docs", dev-flag for `api/users`, standard in `.ai/docs`)
**Supersedes:** architecture parts of `2026-10-17-stack-bootstrap.md` (container and services lived in `app`; `core` was framework-free; `db` could depend on `core`)

## Scope

**In:** the standard's migration steps 1–3 and 7 adapted to MentorHub —
dependency direction `app → core → db` (`ui` used by `app` only) enforced by ESLint; concept
folders; services as classes in `core` with `container.ts`/`cradle.ts`; `env.ts` (zod) and a
redacting `pino` logger; table `users`; shadcn primitives regenerated by the CLI into
`ui/src/components/ui/`; shared server layer `core/src/http` and client layer `ui/src/backend`;
the reference example (`/api/users` + `/admin/users`); `pnpm audit` in `make check`; docs.

**Out:** events (`core/src/events`) and validators (`core/src/validators`) — added with the first
feature that needs them (standard step 4–5, YAGNI); real authentication (own spec); new domain
concepts; persona route groups other than `(marketing)`.

## Acceptance criteria

1. Given the branch, when `make check` runs, then lint, typecheck, tests, build **and
   `pnpm audit --audit-level high`** pass with exit 0; any failure exits non-zero.
2. Given a file that breaks the dependency direction — `next`/`react` imported in `core`,
   `@mentorhub/core|db|app` in `ui`, `@mentorhub/core|app|ui` in `db`, `@mikro-orm/*` outside
   `db`, or a raw `fetch` outside `ui/src/backend/api/apiCall.ts` in `app`/`ui` — when `make lint`
   runs, then it fails.
3. Given the concept convention, then `db/src/entities/auth/user.entity.ts` (on `base.entity.ts`)
   and `core/src/services/{auth/user,health/health}.service.ts` exist, and a reversible migration
   renames table `user` → `users` keeping existing rows.
4. Given `core/src/container/container.ts`, then every dependency is registered by an explicit
   line (no `loadModules`), services are classes registered with `asClass(...).scoped()` (or
   singleton when stateless and DB-free), `cradle.ts` types the cradle, and `withScope(fn)` gives
   each call its own `EntityManager` fork.
5. Given a route wrapped in `apiHandler`, then success returns `{ ok: true, data }`; an
   `AppError` returns its status with `{ ok: false, error: { code, message, fieldErrors? } }`; a
   `ZodError` returns 422 with `fieldErrors`; an unexpected error returns 500 with a generic
   message, no stack trace, and is logged; a non-GET request without the `x-mentorhub-request`
   header returns 403 (CSRF).
6. Given `makeCrudRoute`, then `GET` calls the configured list method, an unconfigured method
   returns 405, and a write body is parsed by its Zod schema so unknown fields never reach the
   service (no mass assignment).
7. Given `requireSession`, then it returns the dev-admin session only when `ALLOW_DEV_ADMIN=1`
   **and** `NODE_ENV !== "production"`; it throws `UnauthorizedError` with the flag missing, with
   the flag in production, or when reading the environment fails (fail closed).
8. Given `core/src/config/env.ts`, then the environment is validated by Zod with documented
   defaults and an invalid value throws at first use; the logger redacts passwords, tokens, JWTs,
   `authorization` and `cookie` fields.
9. Given `packages/ui`, then shadcn primitives are generated by `npx shadcn@latest add` into
   `src/components/ui/`, and `src/backend/` provides `api/apiCall.ts` (+ `readJsonSafe`),
   `forms/CrudForm.tsx`, `tables/DataTable.tsx` and `feedback/{LoadingMessage,ErrorMessage,EmptyState}.tsx`,
   with unit tests for their logic.
10. Given the running app, then `GET /api/users` returns the envelope with users when the dev flag
    is on and 401 when it is off; `/admin/users` renders users through `apiCall` + `DataTable` with
    loading, empty and error states; `/admin` redirects to `/admin/users`; `/` and the
    `/api/health` contract (200/503, `{status, db}`) are unchanged.
11. Given the repo, then the standard is in `.ai/docs/engineering-standards.md`, `AGENTS.md` has the
    standard's section 3 (concept convention, reusable API & UI layer) and the new dependency
    direction, nested `AGENTS.md` files and README match the new structure.

## Risks

- shadcn CLI in a pnpm monorepo writes imports that Turbopack must resolve — mitigated with the
  official monorepo alias pattern (`@mentorhub/ui/...` + package `exports`), checked by the build.
- Moving the container into `core` makes `core` import `db`; the ESLint rules must still keep
  `next`/`react` out of `core`.
- `pnpm audit` depends on the registry; an outage fails `make check` — acceptable (standard).

## Concerns raised

> **CONCERN (security):** `/api/users` exposes emails behind a dev flag, not real auth. Fail-closed
> by design (production ignores the flag), but the auth spec must replace it before any deploy.
